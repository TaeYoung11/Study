# 관통 PJT 관계형 DB 구현 프로젝트 정리

프로젝트에 필요한 데이터를 저장하기 위한 **DB 모델링**, 중복과 이상 현상을 줄이는 **DB 정규화**, 그리고 이를 실제 스키마로 옮기는 **DB 모델링 실습**을 정리한 문서입니다.

---

## 1. DB 모델링

### 모델링 절차

1. **요구사항 분석:** 프로젝트에서 다뤄야 할 데이터(엔터티)와, 그 데이터들 간의 관계를 파악
2. **개념적 설계:** 엔터티(Entity), 속성(Attribute), 관계(Relationship)를 정의한 **ERD(Entity-Relationship Diagram)** 작성
3. **논리적 설계:** 각 엔터티를 테이블로, 관계를 외래키(FK)로 구체화
4. **물리적 설계:** 실제 DBMS(PostgreSQL, MySQL 등)의 데이터 타입, 인덱스 등을 반영해 스키마 확정

### 관계의 종류

| 관계 | 설명 | 구현 방법 |
| --- | --- | --- |
| **1:1** | 한 엔터티의 레코드 하나가 다른 엔터티의 레코드 하나와만 대응 | 한쪽 테이블에 FK + UNIQUE 제약 |
| **1:N** | 한 엔터티의 레코드 하나가 다른 엔터티의 여러 레코드와 대응 | "N" 쪽 테이블에 FK 추가 |
| **N:M** | 양쪽 엔터티가 서로 여러 개씩 대응 | 중간에 별도의 연결(중개) 테이블 필요 |

---

## 2. DB 정규화 (Normalization)

* 하나의 테이블에 데이터를 모두 몰아넣으면 **삽입/갱신/삭제 이상(Anomaly)** 이 발생하기 쉬움 → 이를 줄이기 위해 테이블을 여러 개로 분해하는 과정이 정규화
* 정규화가 되어 있지 않으면 같은 정보가 여러 행에 중복 저장되어, 하나만 수정했을 때 데이터 불일치가 발생할 수 있음

### 정규화 단계 (제1~3 정규형)

| 정규형 | 조건 | 목적 |
| --- | --- | --- |
| **1NF** | 모든 컬럼이 원자값(하나의 값)만 가져야 함 (반복/다중값 금지) | 하나의 셀에 여러 값을 담지 않도록 분리 |
| **2NF** | 1NF를 만족하고, **부분 함수 종속** 제거 (기본키의 일부에만 종속되는 컬럼을 분리) | 복합키 테이블에서의 중복 제거 |
| **3NF** | 2NF를 만족하고, **이행적 종속** 제거 (기본키가 아닌 컬럼이 다른 비-키 컬럼에 종속되는 경우 분리) | 간접적인 중복 제거 |

```
[정규화 전]
주문(주문번호, 고객번호, 고객이름, 상품번호, 상품이름, 수량)
  → 고객이름은 고객번호에, 상품이름은 상품번호에 종속(이행적 종속) → 3NF 위반

[정규화 후]
주문(주문번호, 고객번호, 상품번호, 수량)
고객(고객번호, 고객이름)
상품(상품번호, 상품이름)
```

* 정규화를 지나치게 많이 하면(과도한 테이블 분리) JOIN이 늘어나 조회 성능이 떨어질 수 있어, 실무에서는 상황에 따라 의도적으로 **역정규화(Denormalization)** 를 적용하기도 함

## 3. DB 모델링 실습

### 진행 흐름

1. 프로젝트 주제에서 다룰 주요 엔터티 목록화 (예: 사용자, 게시글, 댓글, 태그)
2. 엔터티 간 관계(1:N, N:M) 파악 및 ERD 작성
3. 3NF 수준까지 정규화된 테이블 스키마로 정리
4. Django `models.py` 등 실제 ORM 모델 코드로 구현

```python
# 예: 게시글(1) - 댓글(N), 게시글(N) - 태그(M) 관계
class Article(models.Model):
    title = models.CharField(max_length=100)
    content = models.TextField()

class Comment(models.Model):
    article = models.ForeignKey(Article, on_delete=models.CASCADE, related_name="comments")
    content = models.TextField()

class Tag(models.Model):
    name = models.CharField(max_length=30)

class ArticleTag(models.Model):   # N:M 관계를 위한 중개 테이블
    article = models.ForeignKey(Article, on_delete=models.CASCADE)
    tag = models.ForeignKey(Tag, on_delete=models.CASCADE)
```

* Django ORM에서는 `ManyToManyField`를 사용하면 중개 테이블을 자동으로 생성해주지만, 중개 테이블에 추가 속성(예: 태그를 붙인 시각)이 필요하면 `through` 옵션으로 직접 중개 모델을 지정

---

## 핵심 요약
* **DB 모델링**은 요구사항 분석 → ERD 작성(개념적 설계) → 테이블/FK 설계(논리적 설계) → 실제 스키마 확정(물리적 설계) 순서로 진행한다.
* **정규화**는 1NF(원자값) → 2NF(부분 함수 종속 제거) → 3NF(이행적 종속 제거) 단계를 거치며 데이터 중복과 이상 현상을 줄이는 과정이다.
* 실습에서는 프로젝트의 엔터티와 관계(1:N, N:M)를 정의한 뒤, 정규화된 스키마를 Django 모델(`ForeignKey`, `ManyToManyField`)로 옮겨 실제 구현까지 이어간다.
