# 관통 PJT 인증 기능 구현 프로젝트 정리

지금까지 진행한 데이터 수집·전처리, 반응형 웹 페이지 구현에 이어, **회원 인증(로그인/회원가입) 기능**을 프로젝트에 통합하는 관통 프로젝트 두 번째 단계 안내를 정리한 문서입니다.

---

## 1. 관통 프로젝트 안내 1 — 목표와 범위

* 지금까지 만든 정적인 페이지에 **사용자 계정 시스템**을 추가해, "누가" 데이터를 수집/조회하는지 구분할 수 있는 서비스로 발전시키는 단계
* 핵심 목표
  1. 회원가입/로그인/로그아웃 기능 구현
  2. 로그인 여부에 따라 접근 가능한 페이지를 다르게 제어 (인증/인가)
  3. 이전 단계에서 만든 데이터 수집·표시 기능을 "로그인한 사용자"에게 연결

### 인증(Authentication) vs 인가(Authorization)

| 구분 | 의미 | 예시 |
| --- | --- | --- |
| **인증(Authentication)** | 사용자가 누구인지 확인하는 과정 | 로그인 (아이디/비밀번호 검증) |
| **인가(Authorization)** | 인증된 사용자가 특정 자원에 접근할 권한이 있는지 확인 | 관리자만 볼 수 있는 페이지 접근 제한 |

---

## 2. 관통 프로젝트 안내 2 — 설계와 진행 방식

### 세션 기반 인증의 기본 흐름

1. 사용자가 아이디/비밀번호로 로그인 요청
2. 서버가 자격 증명을 검증한 뒤, 서버 측에 **세션(Session)** 을 생성하고 세션 ID를 발급
3. 클라이언트는 세션 ID를 **쿠키(Cookie)** 로 저장해, 이후 요청마다 자동으로 함께 전송
4. 서버는 요청에 담긴 세션 ID로 로그인 여부를 판별

```python
# Django 예시 (세션 기반 인증)
from django.contrib.auth import authenticate, login, logout

def login_view(request):
    username = request.POST.get("username")
    password = request.POST.get("password")
    user = authenticate(request, username=username, password=password)
    if user is not None:
        login(request, user)     # 세션 생성 및 로그인 처리
        return redirect("home")
    return render(request, "login.html", {"error": "로그인 실패"})
```

### 진행 순서 제안

1. 데이터 모델에 사용자(User) 개념 추가 (기존 데이터와 사용자를 연결할 외래키 설계)
2. 회원가입/로그인/로그아웃 뷰(View) 및 템플릿 작성
3. 로그인 여부에 따라 접근을 제한하는 데코레이터/미들웨어 적용 (`@login_required` 등)
4. 기존 데이터 수집/표시 기능에 "작성자(로그인 사용자)" 정보를 반영하도록 리팩터링

---

## 핵심 요약
* 인증 기능 구현 프로젝트는 **인증(사용자가 누구인지 확인)** 과 **인가(그 사용자가 무엇을 할 수 있는지 확인)** 를 프로젝트에 통합하는 단계이다.
* 세션 기반 인증은 로그인 시 서버에 세션을 생성하고, 클라이언트는 세션 ID를 쿠키로 보관해 이후 요청마다 자동으로 전송하는 방식으로 동작한다.
* 실제 구현은 "사용자 모델 설계 → 회원가입/로그인/로그아웃 → 접근 제어 → 기존 기능과 연결" 순서로 단계적으로 확장하는 것이 안전하다.
