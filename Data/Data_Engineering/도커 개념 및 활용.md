# 도커 개념 및 활용 정리

컨테이너 기반 가상화 도구인 **Docker**의 핵심 개념(이미지/컨테이너/레지스트리)과 Dockerfile 문법, 그리고 여러 컨테이너를 함께 관리하는 **Docker Compose**를 실습과 함께 정리한 문서입니다.

---

## 1. 컨테이너와 도커 개요

### 컨테이너란?
* **컨테이너(Container):** 애플리케이션과 그 실행에 필요한 라이브러리·설정을 하나로 묶어, 어떤 환경에서도 동일하게 실행할 수 있도록 격리한 실행 단위
* **필요성:** "내 컴퓨터에서는 되는데?" 문제 해결 — 개발/테스트/운영 환경 차이로 인한 오류를 방지하고, 배포와 확장을 간편하게 함

### Container vs VM (가상 머신)
| 구분 | VM (Virtual Machine) | Container |
| --- | --- | --- |
| 가상화 단위 | 하드웨어 가상화 (Hypervisor 위에 Guest OS 전체 실행) | OS 커널 공유, 프로세스 단위 격리 |
| 무게 | 무겁고 느림 (GB 단위, 부팅 시간 소요) | 가볍고 빠름 (MB 단위, 초 단위 기동) |
| 이식성 | 상대적으로 낮음 | 이미지 기반으로 어디서든 동일하게 실행 |

### Docker Architecture
* **Docker Client:** 사용자가 명령어(`docker run`, `docker build` 등)를 입력하는 CLI
* **Docker Daemon(Docker Engine):** 실제로 이미지 빌드, 컨테이너 실행/관리를 수행하는 백그라운드 서비스
* **Docker Registry:** 이미지를 저장하고 배포하는 저장소 (예: Docker Hub)

```
Client → (명령 전달) → Docker Daemon → 이미지 관리 / 컨테이너 실행
                              ↕
                       Docker Registry(Hub)
```

### 도커 핵심 구성요소
| 구성요소 | 설명 |
| --- | --- |
| Docker Engine | 이미지 빌드와 컨테이너 실행을 담당하는 핵심 런타임 |
| Docker Client | 사용자가 명령을 입력하는 CLI 도구 |
| Docker Objects | Image(실행에 필요한 파일·설정을 담은 템플릿), Container(이미지를 실행한 인스턴스), Service(여러 컨테이너를 묶어 제공하는 단위) |
| Docker Registry / Hub | 이미지를 저장·검색·배포하는 공간(Docker Hub가 대표적인 공개 레지스트리) |

### Dockerfile → Docker Image → Docker Container
* **Dockerfile:** 이미지를 만들기 위한 설계도(빌드 명령어 스크립트)
* **Docker Image:** Dockerfile을 빌드해서 나온, 실행 가능한 애플리케이션 템플릿(읽기 전용)
* **Docker Container:** 이미지를 실제로 실행한 상태(쓰기 가능한 인스턴스)

```
Dockerfile --build--> Docker Image --run--> Docker Container
```

**Dockerfile 예시**
```dockerfile
FROM node:16.16.3
WORKDIR /app
ADD . /app
RUN npm install
CMD ["npm", "start"]
```

## 2. Docker 개발 환경 준비

### Docker Desktop 설치 절차
1. Docker 공식 홈페이지에서 운영체제에 맞는 Docker Desktop 다운로드
2. 설치 중 **WSL2 기반 사용** 옵션 선택 (Hyper-V 대신 WSL2 권장 — 더 가볍고 빠름)
3. 구독 계약(subscription agreement) 동의 후 설치 진행
4. 로그인 화면은 Skip 가능 (개인/학습용은 로그인 없이도 사용 가능)
5. Docker Desktop 설정에서 **Ubuntu(WSL) 통합(WSL Integration)** 활성화
6. 설치 확인: `docker run hello-world` 실행 → 정상 메시지 출력 확인

### 실습 디렉토리 준비
```bash
mkdir python-docker-env
cd python-docker-env
echo -e "pandas\nmatplotlib" > requirements.txt
```
* `requirements.txt`: 컨테이너 안에 설치할 파이썬 패키지 목록을 정의하는 파일

### Dockerfile 문법 정리
| 키워드 | 설명 | 예시 |
| --- | --- | --- |
| FROM | 베이스 이미지 지정 | `FROM python:3.10-slim` |
| RUN | 이미지 빌드 시 실행할 명령 (패키지 설치 등) | `RUN pip install -r requirements.txt` |
| COPY | 로컬 파일을 이미지 안으로 복사 | `COPY requirements.txt .` |
| WORKDIR | 컨테이너 내부의 작업 디렉토리 설정 | `WORKDIR /workspace` |
| ENV | 컨테이너 내부 환경 변수 설정 | `ENV MODE=production` |
| EXPOSE | 컨테이너가 사용할 포트 명시(문서화 목적) | `EXPOSE 8080` |
| CMD | 컨테이너 시작 시 실행할 기본 명령 | `CMD ["python", "app.py"]` |

**실습 Dockerfile 예시**
```dockerfile
FROM python:3.10-slim
WORKDIR /workspace
COPY requirements.txt .
RUN pip install --upgrade pip && pip install -r requirements.txt
COPY app.py .
CMD ["python", "app.py"]
```

## 3. Docker 기본 명령어

### 이미지 관련 명령어
| 명령어 | 설명 |
| --- | --- |
| docker search [이름] | Docker Hub에서 이미지 검색 |
| docker pull [이미지명] | 이미지 다운로드 |
| docker images (= docker image ls) | 로컬 이미지 목록 확인 |
| docker rmi [이미지ID/이름] | 이미지 삭제 |
| docker tag [기존이름] [새이름] | 이미지에 별칭(tag) 붙이기 |
| docker build -t [이미지이름] . | 현재 디렉토리의 Dockerfile로 이미지 빌드 |

### 컨테이너 실행 & 관리 명령어
| 명령어 | 설명 |
| --- | --- |
| docker run [이미지] | 컨테이너 실행 |
| docker run -it [이미지] | 대화형 실행 (터미널 접근) |
| docker run -d [이미지] | 백그라운드 실행 (detached mode) |
| docker run --name [이름] [이미지] | 컨테이너에 이름 부여 후 실행 |
| docker ps | 실행 중인 컨테이너 목록 |
| docker ps -a | 모든 컨테이너 목록 (종료 포함) |
| docker stop [이름/ID] | 컨테이너 정지 |
| docker restart [이름/ID] | 컨테이너 재시작 |
| docker rm [이름/ID] | 컨테이너 삭제 |

### 컨테이너 내부 다루기
| 명령어 | 설명 |
| --- | --- |
| docker exec [이름] [명령] | 실행 중 컨테이너에 명령 실행 |
| docker exec -it [이름] bash | 실행 중 컨테이너 내부로 접속 |
| docker cp [파일] [컨테이너]:[경로] | 컨테이너에 파일 복사 |
| docker container stats [이름] | 컨테이너 리소스 사용량 확인 |

**실습 흐름 예시**
```bash
docker build -t python-lab .              # Dockerfile 기반 이미지 빌드('python-lab' 태그)
docker run -it --name pycheck python-lab  # 대화형 모드로 컨테이너 실행
docker ps -a                              # 실행했던 컨테이너까지 모두 확인
docker stop pycheck                       # 컨테이너 정지
docker rm pycheck                         # 컨테이너 삭제
docker images                             # 로컬 이미지 확인
docker rmi {이미지ID}/hello-docker:v1     # 로컬 이미지 삭제
```

## 4. Docker Compose

### Docker Compose란?
* 여러 컨테이너를 하나의 프로젝트처럼 묶어서 관리할 수 있게 해주는 도구
* `docker-compose.yml` 파일에 정의된 내용을 바탕으로 한 번에 여러 컨테이너를 실행/종료

### docker-compose.yml 구조
```yaml
services:
  web:
    image: nginx
    ports:
      - "8080:80"
  db:
    image: mongo
```
* **services:** 컨테이너(서비스) 목록
* **image:** 사용할 도커 이미지
* **ports:** 호스트와 컨테이너의 포트 매핑

### Docker Compose 명령어
| 명령어 | 설명 |
| --- | --- |
| docker compose up -d | 정의된 모든 서비스(컨테이너)를 생성하고 백그라운드로 실행 |
| docker compose ps | 현재 Compose로 실행 중인 컨테이너 상태 확인 |
| docker compose down | 실행 중인 모든 컨테이너, 네트워크, 볼륨 종료 및 삭제 |
| docker compose logs [-f] | 컨테이너 로그 출력 (`-f`: 실시간 로그) |
| docker compose stop / start / restart | 컨테이너 중지 / 재시작 / 재시작 |
| docker compose build | Dockerfile 기반으로 이미지 빌드 |
| docker compose exec [서비스명] [명령] | 실행 중인 컨테이너에서 명령어 실행 (예: `docker compose exec web bash`) |
| docker compose run --rm [서비스명] | 새로운 일회성 컨테이너 실행 |

### 실습: Docker Compose로 Nginx + MongoDB 띄우기
```bash
mkdir compose-lab
cd compose-lab
touch docker-compose.yml
touch index.html
```

**index.html**
```html
<!-- index.html -->
<!DOCTYPE html>
<html>
<head><title>Docker Compose Web</title></head>
<body><h1>Hello from Nginx!</h1></body>
</html>
```

**docker-compose.yml**
```yaml
services:
  web:
    image: nginx
    ports:
      - "8080:80"
    volumes:
      - ./index.html:/usr/share/nginx/html/index.html
  db:
    image: mongo
    ports:
      - "27017:27017"
```

```bash
docker compose up -d     # 정의된 모든 서비스를 생성하고 실행 (백그라운드)
docker compose ps        # 실행 중인 컨테이너 목록 확인
```
* `localhost:8080` 접속 시 "Hello from Nginx!" 정상 출력 확인 가능

```bash
docker compose down      # 컨테이너 + 네트워크 정리
docker compose ps        # 정리된 것(빈 목록) 확인 가능
```
* 정리 이후에는 `localhost:8080` 접속이 되지 않음

### 자주 쓰이는 docker-compose.yml 문법
| 키워드 | 용도 | 예시 |
| --- | --- | --- |
| services | 실행할 컨테이너(서비스)들을 정의하는 최상위 키. 각 서비스별 이미지, 포트, 볼륨 등 설정 | `services: web: …` |
| image | 사용할 도커 이미지를 지정 | `image: nginx:latest` |
| build | 로컬의 Dockerfile로 이미지를 직접 빌드할 때 사용 | `build: ./app` |
| container_name | 컨테이너 이름을 직접 지정(안 하면 자동 생성) | `container_name: my_app` |
| ports | 호스트 ↔ 컨테이너 포트 연결. `"호스트:컨테이너"` 형식 | `ports: - "8080:80"` |
| volumes | 데이터 공유/저장. 로컬 디렉토리를 컨테이너에 마운트하거나 볼륨을 이름으로 저장 | `volumes: - ./data:/var/lib/mysql` |
| environment | 컨테이너 내부의 환경 변수 직접 지정 | `environment: - MYSQL_ROOT_PASSWORD=1234` |
| env_file | `.env` 파일에서 환경 변수 한꺼번에 가져오기 | `env_file: - .env` |
| command | 컨테이너 시작 시 실행할 명령어(Dockerfile의 CMD를 덮어씀) | `command: python app.py` |

**상위 레벨 키워드**
| 키워드 | 용도 | 예시 |
| --- | --- | --- |
| volumes(최상위) | 여러 서비스가 공유하는 데이터 볼륨 정의 | `volumes: db_data:` |
| networks | 사용자 정의 네트워크 생성(컨테이너 간 별도 통신망 필요 시) | `networks: my_network:` |

### Docker Compose 네트워크
* **같은 Compose 파일 내 네트워크:** `docker compose up` 실행 시 자동으로 프로젝트 이름 기반의 네트워크가 생성되며, 같은 파일 내 서비스들은 동일 네트워크를 공유하므로 서로 통신 가능
  * 서비스명으로 접근 권장 — Docker가 자동으로 DNS를 관리하므로, IP보다 `db`처럼 서비스명으로 접근하는 것이 일반적이고 안전(IP는 컨테이너 재시작 시 바뀔 수 있음)
* **다른 Compose 프로젝트 간 네트워크:** 기본적으로 프로젝트 간 네트워크는 분리되어 서로 통신할 수 없음. 명시적으로 같은 사용자 정의 네트워크를 지정하면 서로 통신 가능하며, 서로 다른 `docker-compose.yml`에서 미리 만든 외부 브리지 네트워크에 `external: true` 옵션을 사용하면 IP/서비스명 공유 가능
* 서비스명으로 접근할 때는 동일 네트워크 내에서만 가능하고, 외부 네트워크 간 통신을 위해선 명시적으로 네트워크 설정 필요

## 핵심 요약
* **컨테이너**는 애플리케이션과 실행 환경을 하나로 묶어 격리한 실행 단위로, VM보다 가볍고 빠르며 이식성이 뛰어납니다. Docker는 Client-Daemon-Registry 구조로 동작하며, 핵심 오브젝트는 **Image(설계도) → Container(실행 인스턴스)** 입니다.
* **Dockerfile**은 `FROM/WORKDIR/COPY/RUN/CMD` 등의 키워드로 이미지 빌드 과정을 정의하며, `docker build`로 이미지를 만들고 `docker run`으로 컨테이너를 실행합니다.
* 기본 명령어는 이미지 관리(`pull/images/rmi/build`), 컨테이너 관리(`run/ps/stop/rm`), 컨테이너 내부 작업(`exec/cp`)으로 구분됩니다.
* **Docker Compose**는 `docker-compose.yml`에 여러 서비스(컨테이너)를 정의해 `docker compose up/down` 한 번으로 관리할 수 있게 해주며, 같은 파일 내 서비스들은 자동 생성된 네트워크를 공유해 서비스명으로 서로 통신합니다.
