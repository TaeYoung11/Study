# DB N:1 2 정리

**Article과 User**, **Comment와 User** 사이의 N:1 관계를 추가로 연결하는 방법과, 여러 URL을 하나의 View로 처리하는 **View Decorators**, 그리고 복잡해진 테이블 관계를 한눈에 정리하는 **ERD**를 정리한 문서입니다.

---

## 1. Article & User (작성자 연결)

* 지금까지의 게시글에는 "누가 작성했는지" 정보가 없었으므로, `User`와 N:1 관계를 추가로 맺어 작성자를 기록

```python
from django.conf import settings

class Article(models.Model):
    user = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    title = models.CharField(max_length=100)
```

* `settings.AUTH_USER_MODEL`을 사용하는 이유: User 모델을 직접 import하는 대신 이렇게 참조하면, 프로젝트마다 다른 커스텀 유저 모델을 사용하더라도 코드를 그대로 재사용할 수 있음

```python
def create(request):
    form = ArticleForm(request.POST)
    if form.is_valid():
        article = form.save(commit=False)
        article.user = request.user     # 현재 로그인한 사용자를 작성자로 지정
        article.save()
        return redirect("articles:index")
```

## 2. Comment & User

* 댓글에도 동일한 패턴으로 작성자를 연결

```python
class Comment(models.Model):
    article = models.ForeignKey(Article, on_delete=models.CASCADE)
    user = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.CASCADE)
    content = models.CharField(max_length=200)
```

* 하나의 Comment가 **Article, User 두 개의 FK**를 동시에 가지는 구조 — "이 댓글은 어느 글에, 누가 작성했는가"를 모두 표현

## 3. View Decorators

* 게시글/댓글 작성, 삭제 등은 로그인한 사용자만 가능해야 하므로, View 함수에 데코레이터를 적용해 접근을 제어

```python
from django.contrib.auth.decorators import login_required
from django.views.decorators.http import require_POST, require_http_methods

@login_required
@require_POST
def delete(request, pk):
    article = get_object_or_404(Article, pk=pk)
    if request.user == article.user:    # 작성자 본인 확인
        article.delete()
    return redirect("articles:index")

@require_http_methods(["GET", "POST"])
def create(request):
    ...
```

* `@login_required`: 비로그인 사용자의 접근을 로그인 페이지로 리다이렉트
* `@require_POST`: GET 요청으로는 접근할 수 없도록 제한 (삭제처럼 상태를 바꾸는 View에 필수)
* 데코레이터는 여러 개를 겹쳐서 함께 사용 가능

---

## 4. ERD (Entity-Relationship Diagram)

지금까지 만든 모델 관계를 정리하면 다음과 같습니다.

```
User (1) ─────< (N) Article
  │                    │
  │ (1)                │ (1)
  │                    │
  └───< (N) Comment >──┘
```

* `Article.user` → User를 참조하는 N:1
* `Comment.article` → Article을 참조하는 N:1
* `Comment.user` → User를 참조하는 N:1

* 모델이 늘어날수록 ERD로 전체 관계를 한눈에 정리해두면, 새로운 기능을 추가할 때 어떤 테이블에 어떤 FK가 필요한지 빠르게 파악할 수 있음

---

## 핵심 요약
* Article과 Comment 모두 `settings.AUTH_USER_MODEL`을 참조하는 `ForeignKey`로 작성자(User)를 연결하며, 저장 시 `request.user`를 지정해 로그인한 사용자를 작성자로 기록한다.
* **View Decorator**(`login_required`, `require_POST` 등)를 조합하면, 로그인 여부와 허용할 HTTP 메서드를 함수 단위로 선언적으로 제어할 수 있다.
* 모델 관계가 늘어날수록 **ERD**로 전체 구조를 시각화해두면 유지보수와 신규 기능 설계에 유리하다.
